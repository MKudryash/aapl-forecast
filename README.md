# Прогнозирование дневной цены закрытия AAPL: сравнительное исследование методов

Практики 8-9 курса «Анализ данных и машинное обучение», группа 1.
Инструмент: акции Apple, котировки CFD **AAPL.US/USD** (Dukascopy).

**Главный результат.** На тестовом периоде (60 точек прогноза, 28.07.2026 - 20.10.2026) ни одна из моделей
(ARIMA, ETS, LightGBM, GRU) **статистически значимо не превзошла наивный прогноз** ни на горизонте 1 день,
ни на горизонте 5 дней. LightGBM на горизонте 1 день значимо **хуже** наивного прогноза (тест Диболда-Мариано, MSE, p = 0.025).
Небольшой выигрыш на горизонте 5 дней (Drift -4.6% MAE, ETS -2.0%, GRU -2.4%) объясняется восходящим трендом
цены за год и статистически не подтверждается. Результат согласуется с отсутствием автокорреляции доходностей
(тест Льюнга-Бокса, p ≈ 0.5) и с гипотезой слабой эффективности рынка.

## 1. Постановка задачи и гипотезы

**Задача.** По истории дневных котировок AAPL спрогнозировать цену закрытия на **1 и 5 торговых дней вперед**
и сравнить не менее четырех подходов: наивный прогноз, классический статистический метод,
метод машинного обучения и нейросетевой метод.

**Исследовательские вопросы**
- В1. Превосходят ли сложные модели наивный прогноз (случайное блуждание) по точности?
- В2. Как меняется качество и соотношение моделей при росте горизонта с 1 до 5 дней?
- В3. Насколько устойчивы выводы к выбору тестового подпериода, типа окна обучения и случайной инициализации?
- В4. Оправданы ли вычислительные затраты сложных моделей?

**Гипотезы**
- Г1. Дневные доходности AAPL практически не автокоррелированы, поэтому ни одна модель не даст значимого выигрыша над наивным прогнозом.
- Г2. Ошибка растет с горизонтом примерно пропорционально √h.
- Г3. Сложные модели на годовой выборке (~190 обучающих наблюдений) склонны к переобучению и могут проигрывать простым.

**Формирование дневной свечи.** Свеча агрегирует котировки CFD за календарные сутки UTC.
Американская сессия (13:30/14:30 - 20:00/21:00 UTC в зависимости от летнего времени) целиком попадает в эти сутки,
поэтому `close` близок к цене закрытия NASDAQ, но не обязан с ней совпадать.

**Торговые и неторговые дни, пропуски** (`src/data.py`, отчет `results/cleaning_report.json`):
- выходные: удаляются (в данной выгрузке их уже нет);
- праздники биржи: Dukascopy может отдавать «плоские» свечи (`high == low`, объем 0), они удаляются как ненастоящие цены (в данной выгрузке их нет);
- дубликаты дат и строки с ценой ≤ 0: удаляются (не обнаружены);
- пропущенные будние дни: 10, все совпадают с праздниками NYSE (27.11.2025, 25.12.2025, 01.01.2026, 19.01.2026, 16.02.2026, 03.04.2026, 25.05.2026, 19.06.2026, 03.07.2026, 07.09.2026). Они **не заполняются**: ряд индексируется торговыми днями, горизонт h означает h торговых дней.

Очищенный ряд: `data/aapl_d1_clean.csv`.

## 4. Схема исследования

**Разбиение по времени.**

| Часть | Период | Наблюдений |
|---|---|---|
| Начальная обучающая выборка | 28.10.2025 - 28.07.2026 | 187 |
| в т.ч. хвост для подбора гиперпараметров | последние 40 дней этой части | 40 |
| Тест: точки прогноза (origins) | 28.07.2026 - 20.10.2026 | 60 |
| Тест: прогнозируемые даты | 29.07.2026 - 27.10.2026 | |

**Walk-forward валидация** (`src/evaluation.py`, функция `walk_forward`). Для каждой точки прогноза t:
1. модели передается только история `df[0 : t]` включительно (расширяющееся окно);
2. при необходимости модель переобучается на этой истории;
3. строится прогноз на t+1, ..., t+5;
4. прогноз сравнивается с фактом.

**Защита от утечки будущего:**
- модель физически получает только прошлое (`hist`), будущие строки ей не передаются;
- признаки строятся только через сдвиги назад (`shift`, `rolling`);
- нормализация для нейросети считается по обучающим данным;
- гиперпараметры подбираются **один раз** на хвосте начальной выборки, до теста; при подборе LightGBM в обучение берутся только строки, цель которых целиком заканчивается до начала валидации;
- проверка на синтетическом случайном блуждании: ни одна модель не обгоняет наивный прогноз (MAE/Naive 0.97-1.08), что ожидаемо при отсутствии утечки.

**Сопоставимость.** Набор из 60 точек прогноза одинаков для всех моделей и обоих горизонтов
(для каждой точки известны факты и на t+1, и на t+5).

**Метрики** (`metrics` в `src/evaluation.py`):
- **MAE**, USD — средняя абсолютная ошибка;
- **RMSE**, USD — сильнее штрафует крупные промахи;
- **sMAPE**, % = `mean(2|y - ŷ| / (|y| + |ŷ|)) · 100`;
- **DirAcc**, % — доля совпадений знака прогнозного и фактического изменения цены относительно `P[t]`. Для наивного прогноза (и ARIMA(0,1,0)) прогнозное изменение равно 0, поэтому метрика не определена (NaN). Ориентир: доля роста в тесте = 53.3% (h=1) и 66.7% (h=5), то есть результат стратегии «всегда рост»;
- **MAE_vs_Naive** — отношение MAE модели к MAE наивного прогноза (< 1 — лучше baseline);
- **тест Диболда-Мариано** с поправкой Harvey-Leybourne-Newbold против наивного прогноза, функции потерь MSE и MAE, автокорреляция ошибок до лага h-1.

## 5. Методы

| Модель | Тип | Что прогнозирует | Подбор | Переобучение |
|---|---|---|---|---|
| Naive | baseline | `P[t+h] = P[t]` | — | — |
| Drift | baseline | `P[t]·exp(h·μ)`, μ — средняя лог-доходность за всю историю | — | каждая точка |
| ARIMA(p,1,q) | статистический | лог-цена | p,q ∈ {0,1,2}, снос да/нет, по AIC | каждая точка |
| ETS | статистический | лог-цена, Холт с затухающим трендом | MLE | каждая точка |
| LightGBM | ML | накопленная лог-доходность, 5 моделей (прямая стратегия) | сетка 8 комбинаций | каждые 5 точек |
| GRU | нейросеть | 5 накопленных лог-доходностей одним выходом | L ∈ {10,20}, hidden ∈ {8,16} | каждые 20 точек |

**ARIMA.** Перебор 18 вариантов на начальной выборке (`results/tuning_arima.csv`).
По AIC выбрана **ARIMA(0,1,0) без сноса**, то есть случайное блуждание. Поэтому прогнозы ARIMA совпадают с наивными.
Это самостоятельный результат: статистический критерий не нашел в ряду структуры, оправдывающей AR- или MA-компоненты.

**ETS.** Аддитивный тренд с затуханием, чтобы прогноз не продлевал тренд неограниченно.

**LightGBM.** 22 признака (`src/features.py`): 10 лагов лог-доходности, скользящие среднее и стандартное отклонение
за 5/10/20 дней, отклонение цены от 20-дневной средней, лог-размах `ln(high/low)` с лагами 0-2,
`ln(close/open)`, день недели. Прямая стратегия: отдельная модель для каждого h = 1..5, без накопления ошибок рекурсии.
Работа с доходностями, а не с ценой, обязательна: деревья не экстраполируют за диапазон обучения.
Выбрано (`results/tuning_lightgbm.csv`): `num_leaves=8, n_estimators=100, learning_rate=0.03, min_child_samples=20`,
плюс `subsample=0.8, colsample_bytree=0.8, reg_lambda=1`. Выбор самой простой и сильнее регуляризованной конфигурации
согласуется с малым объемом данных.

**GRU.** Вход: окно из L дней × 2 признака (лог-доходность, `ln(high/low)`), стандартизованные по обучающим данным.
Один слой GRU, Dropout 0.2, линейный выход на 5 горизонтов. Adam (lr = 1e-3, weight decay = 1e-4), батч 32, до 300 эпох,
**ранняя остановка** по последним 15% окон обучения (терпение 25 эпох). Выбрано (`results/tuning_gru.csv`): L = 10, hidden = 8.
Итоговый прогноз — **среднее ансамбля из 5 сетей** с разными seed. Предобученные модели не использовались.
Малая сеть выбрана сознательно: обучающих окон около 170, большая сеть запомнила бы данные.

Частота переобучения у LightGBM и GRU снижена ради вычислительных затрат. Корректность не нарушается:
в каждой точке используется модель, обученная только на прошлом.

### 6.3. Прогнозы и ошибки

![Прогнозы](results/figures/03_forecasts.png)

На h=1 все прогнозы фактически повторяют вчерашнюю цену со сдвигом на день. Это типичная картина для случайного блуждания:
модель не предсказывает изменение, а «запаздывает» за фактом.

![Накопленная ошибка](results/figures/05_cum_error_vs_naive.png)

Накопленная разница абсолютных ошибок с наивным прогнозом (ниже нуля — модель лучше):
- h=1: у LightGBM и GRU линия устойчиво растет, они проигрывают с первых недель теста; Drift и ETS колеблются около нуля;
- h=5: Drift и ETS уходят ниже нуля только с сентября, GRU только в октябре, то есть в период устойчивого роста цены; у LightGBM сильные колебания в обе стороны.

### 6.4. Влияние горизонта

MAE наивного прогноза растет с 3.47 $ (h=1) до 7.06 $ (h=5), в 2.03 раза. Для случайного блуждания ожидается √5 ≈ 2.24.
Это близко и подтверждает гипотезу Г2. С ростом горизонта немного выигрывают модели, учитывающие тренд (Drift, ETS):
за 5 дней систематический снос накапливается, а на 1 дне он тонет в шуме.

Точность направления Drift и ETS (53.3% на h=1, 66.7% на h=5) в точности равна доле роста в тесте:
обе модели прогнозировали рост во всех 60 точках на обоих горизонтах. GRU прогнозировал рост в 52% точек на h=1 и в 88% на h=5,
LightGBM в 57% и 82%. Это эффект тренда тестового периода, а не умение угадывать направление.
GRU на h=1 угадывает направление в 41.7% случаев — хуже, чем «всегда рост» (53.3%).

| LightGBM | 12 | 2.4 | 0.8 | 3.2 |
| ARIMA | 60 | 3.7 | 0.08 | 3.7 |
| GRU (5 сетей) | 3 | 36.2 | 0.17 | 36.4 |

Без учета подбора гиперпараметров. GRU требует в ~10 раз больше времени, чем LightGBM и ARIMA, и примерно в 10⁴ раз больше,
чем наивный прогноз, не давая значимого выигрыша.

## 9. Обсуждение

**Почему сложные модели не выигрывают.** Доходности AAPL не автокоррелированы (Льюнг-Бокс p ≈ 0.5, ACF(1) = 0.03),
поэтому прошлые цены почти не содержат информации о будущих изменениях. Это соответствует слабой форме гипотезы
эффективного рынка. Лучшее, что модель может сделать в такой ситуации, — повторить последнюю цену.
Попытка найти закономерность там, где ее нет, приводит к подгонке под шум.

**Почему LightGBM и GRU хуже на h=1.** На ~190 наблюдениях с отношением сигнал/шум, близким к нулю, гибкие модели
выучивают случайные паттерны обучающей выборки. Их прогнозы изменения ненулевые, но не коррелируют с фактическими
изменениями, и это лишь добавляет дисперсию к ошибке. Выбор при подборе самых простых конфигураций
(100 деревьев, 8 нейронов, L = 10) — косвенный признак того же.

**Почему трендовые модели немного выигрывают на h=5.** За год цена выросла на 29%, а тестовый период после падения
в конце июля был периодом устойчивого роста. Модели, экстраполирующие положительный снос, получили преимущество.
Это не подтверждено статистически (DM p ≥ 0.25), неустойчиво по подпериодам и в периоде падения (блок 1) исчезает.
На другом отрезке времени, например при нисходящем тренде, эффект может смениться на противоположный.

**Что подтверждено экспериментально, а что — гипотезы:**
- *Подтверждено:* ни одна модель значимо не лучше наивного прогноза; LightGBM значимо хуже на h=1; ошибка растет с горизонтом близко к √h; ARIMA по AIC выбирает случайное блуждание; результат GRU заметно зависит от seed.
- *Гипотезы, не проверенные напрямую:* выигрыш трендовых моделей на h=5 вызван ростом цены в тестовом периоде; на более длинной истории или с внешними признаками (новости, отчетность, рыночные индексы) сложные модели могли бы выиграть.

**Ответы на исследовательские вопросы.**
- В1: нет (Г1 подтверждена).
- В2: ошибка растет примерно как √h; на h=5 трендовые модели незначимо выигрывают (Г2 подтверждена).
- В3: ранжирование моделей неустойчиво; устойчив только проигрыш LightGBM на h=1.
- В4: нет, затраты сложных моделей выше на порядки без выигрыша в точности (Г3 подтверждена).

## 10. Выводы, ограничения и условия применения

**Выводы**
1. Для прогноза дневной цены закрытия AAPL на 1-5 дней по одной только истории цен наивный прогноз остается
   сильнейшим практическим ориентиром: ARIMA, ETS, LightGBM и GRU значимо его не превосходят.
2. Итоговый рекомендуемый метод — **наивный прогноз (случайное блуждание)**: та же точность при нулевых затратах
   и полной интерпретируемости. На горизонте 5 дней допустим Drift или ETS, но их выигрыш (2-5% MAE) незначим и зависит от тренда.
3. Повышение сложности модели на годовой выборке не повышает точность, а увеличивает риск переобучения и
   зависимость от случайной инициализации.

**Ограничения**
- Один год данных (251 наблюдение); тест из 60 точек дает низкую мощность статистических тестов.
- Один инструмент и один рыночный режим (рост цены); выводы о трендовых моделях не переносятся на другие периоды.
- Котировки CFD Dukascopy, а не биржевые цены NASDAQ.
- Только ценовые признаки; не использованы объемы торгов, отчетность, новости, индексы, опционные данные.
- Перекрывающиеся 5-дневные прогнозы зависимы; это учтено в тесте DM, но эффективный объем выборки меньше 60.
- Гиперпараметры подбирались один раз на начальной выборке и на небольших сетках.
- LightGBM и GRU переобучались реже, чем статистические модели.

**Условия практического применения.** Модели не следует использовать для торговых решений:
точность направления не превосходит стратегию «всегда рост». Полученные результаты можно использовать как
обоснование baseline для будущих исследований. Для практической пользы нужны внешние признаки, более длинная история,
прогноз волатильности и интервальные прогнозы вместо точечных.

## 11. Воспроизведение

Требуется Python 3.10+ (проверено на 3.13 и на macOS).

```bash
git clone <ссылка на репозиторий>
cd aapl-forecast
./run.sh          # создает .venv, ставит зависимости, запускает эксперимент
```
или вручную:
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python src/run_all.py
```

Время прогона: 2-3 минуты на обычном ноутбуке. Все seed зафиксированы; метрики воспроизводятся до последнего знака
(проверено на двух машинах: Linux и macOS). Время работы моделей от запуска к запуску немного меняется.

Если на macOS LightGBM выдает ошибку про `libomp`: `brew install libomp`.

**Получение данных заново:**
```bash
npx dukascopy-node -i aaplususd -from 2025-10-28 -to 2026-10-28 -t d1 -p bid -f csv -dir data/raw
```
